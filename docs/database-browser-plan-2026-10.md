# 数据库浏览器改进计划

- 生成日期：2026-10-19
- 范围：`RagnarokOffline/Database/` 下的 8 个数据库（物品、职业、地图、怪物、召唤组、宠物、技能、状态），以及它们共用的组件：`ImageGrid`、`ImageGridCell`、`SectionHeaderView`、`SelectableButton`、`Stretchy`。

## 约定

- 条目按重要程度编号，从 1 开始依次往下做。
- 优先级
  - **P0**：影响能不能找到数据、看不看得懂。
  - **P1**：明显提高查找和阅读的效率。
  - **P2**：一致性和细节打磨。
  - **P3**：锦上添花。
- 一次只改一个点，改完停下来等 review。条目太大时拆成几次改。

## P0

### 1. 统一搜索规则

- 现状：
  - 只有物品、怪物、技能能用 `#ID` 搜索。地图、职业、状态不行。
  - 大多只匹配 `displayName`。地图在宽屏布局里显示了内部名（比如 `prt_fild08`），但用内部名搜不到。
  - 各列表的过滤写在 `.task(id: filter.identifier)` 里。每按一次键，都在 MainActor 上把整个数组过滤一遍，没有 debounce。物品有上万条，每条都要调用 `localizedStandardContains`，所以打字时会卡。
- 目标：
  - 所有库都能用 `#ID`、本地化名、原名、Aegis 名搜索。地图还要能用内部名搜索。
  - 搜索输入加 debounce，过滤移到 MainActor 之外执行。

### 2. 补全详情数据

用户打开数据库主要就是为了查这些信息。按库拆成几次来改。

- 技能：
  - 增加每个等级的数据表：SP、施法时间、延迟、射程。
  - 列出哪些职业能学这个技能。
  - 修正 `DatabaseModel.skills(for:)`：它读取 `jobs` 之前没有先调用 `fetchJobs()`。
- 怪物：怪物技能（mob_skill_db）、属性伤害倍率表。
- 物品：
  - "Dropped By" 按掉率从高到低排序。
  - NPC 商店来源，从 `scriptCommands` 取。
  - 宠物用途：捕捉道具、宠物蛋、宠物装备、宠物食物。
- 地图：mapflag、传送点、NPC，以及"在 Map Viewer 中打开"的入口。

### 3. 数值和标签的显示

- 现状：
  - 同一页里，有的字段用 `localizedName`（类型、种族），有的用 `stringValue`（体型、属性、弹药类型、卡片类型、技能类型）。结果是中文和英文枚举名混在一起。
  - Jobs、Classes、Locations、Race Groups、Modes 显示为 `"- xxx"` 换行的纯文本，内容是原始枚举名。
  - 掉率和数量写成 `(25%)`、`(5x)` 这样的括号文字。
- 目标：
  - 所有字段统一显示本地化名称。
  - 列表类字段改成 flow layout 的 chip。
  - 掉率和数量改成胶囊 badge，并按掉率区间着色：低于 0.1% 算稀有，高于 10% 算常见。

### 4. 像素图插值

- 现状：工程里没有一处用 `.interpolation(.none)`。下面这些图都是 `.resizable()` 后用默认插值放大的，边缘发糊：
  - 物品图标：原图 24×24，显示为 40pt。
  - 物品预览图和地图图片：显示高度 200pt。
- 目标：放大像素图时使用 `.interpolation(.none)`。怪物精灵在 `MonsterImageView` 里只会缩小，不受这个问题影响。
- 这条只需要改几行，可以提前做。

## P1

### 5. 宽屏列表改用 `Table`

- 现状：物品、技能、地图在 regular 布局下用 `HStack` 固定列宽，没有表头，也不能排序。
- 目标：iPad 和 macOS 上改用 SwiftUI `Table` + `sortOrder`。各库的列如下：
  - 物品：名称、类型、买价、卖价、重量。
  - 怪物：名称、等级、HP、Base Exp、Job Exp、种族、属性、体型。
  - 技能：名称、最大等级、SP 消耗。

### 6. 补充筛选项

- 新增筛选维度：
  - 怪物：等级范围、MVP/Boss（`class`）。
  - 物品：槽位数、可装备职业、装备等级。
  - 技能：职业、类型。
- 交互改进：
  - 有筛选生效时，工具栏按钮要显示出来，比如换成填充图标或加 badge。
  - 单选项（类型、体型、种族、属性）再点一次可以取消。
  - "No Results" 页面加一个 Reset Filters 按钮。

### 7. 信息分组和语义色

- 现状：
  - 每个 section 都是 `title3` 标题加一条 `Divider`，看起来分量都一样。
  - 怪物大约有 40 个属性，全挤在一个两列网格里。
  - 网格最小列宽是 280，宽屏上标签和数值之间隔得太远。
  - 数字没有用等宽数字，整页只有一种颜色。
- 目标：
  - 属性分组显示。比如怪物分成基础、六维、战斗、速度与动作四组。
  - 限制列宽，或者改成标签在上、数值在下的紧凑布局。
  - 数字使用 `.monospacedDigit()`。
  - 属性元素、MVP/Boss、物品类型用颜色或 badge 区分。

### 8. 列表副标题和网格标记

- 现状：
  - compact 布局的副标题显示的是 `aegisName`（`ItemCell`、`SkillCell`）。
  - `StatusChangeCell` 没有副标题，行高和其他 cell 不一样。
  - 怪物网格只显示名字。
- 目标：
  - 副标题改成有用的摘要。比如物品显示"武器 · 短剑 · 50z"，技能显示"Lv.10 · 主动"。
  - 怪物网格加上等级、MVP 标记和属性色点。

## P2

### 9. 统一详情页头

- 现状：
  - 技能和状态的详情页没有 hero 区。
  - 职业详情显示静态首帧，怪物详情显示动画。
  - "加载中"和"没有图片"显示的是同一个细线 SF Symbol，分不出来。
  - hero 区高 200pt，背景空白，小精灵放在里面显得很空。
- 目标：
  - 所有库都用同一种页头：大图或图标 + 名字 + `#ID`。
  - 加载中显示占位，和"没有图片"区分开。
  - 在精灵下面加一层淡渐变底或地面阴影。

### 10. 职业等级表

- 现状：
  - 用 `HStack` 把四列等分，其中一列用空的 `Text(verbatim: "")` 占位。
  - 175 行全部展开，往下滚就看不到表头了。
- 目标：改用 `Grid` 或 `Table`，表头固定，加斑马纹，去掉空列。

### 11. 交互反馈

- 现状：网格 cell 用的是 `.borderless` 按钮样式，没有 `hoverEffect`。在 iPad 指针、macOS 鼠标、visionOS 注视下几乎没有反馈。
- 目标：
  - 网格 cell 加上 hover 和按下效果。
  - 筛选按钮的选中状态更明显，比如用 `.borderedProminent` 或加勾选图标。

### 12. Pre-renewal 模式

- 现状：`App/AppModel.swift:48` 写死了 `DatabaseModel(mode: .renewal, ...)`。`MonsterModel` 等模型已经实现了 pre-renewal 分支，比如最小和最大攻击，但现在用不到。
- 目标：提供模式切换（放在设置里，或放在数据库工具栏上），切换后重新加载数据库。

## P3

### 13. 复制 ID 和 Aegis 名

- 属性值支持选中复制，或者通过右键菜单复制 ID 和 Aegis 名。
