# Server Configuration 分阶段实施计划

配置范围见 [实现清单](CONFIGURATION_CHECKLIST.md)。本文记录实施顺序、每日工作范围、交付物和验收标准；实现过程中持续更新状态和实际结果。

当前状态：完成配置盘点，尚未开始可视化编辑实现。现有 `ServerConfigurationView` 只读展示配置文本。

## 工作量与执行规则

- 每个 phase 约 1 人天，按一名熟悉 SwiftUI 和项目结构的开发者约 6 小时有效开发时间估算，包含必要验证与文档更新。
- 按依赖顺序推进。每天结束应有可演示结果，不以“写完代码但未验证”作为完成。
- 表中为计划工作包，不是固定工期承诺。字段语义复杂或超量时，拆成编号带后缀的后续 phase，不能省略验证凑工期。
- 常规字段每个 phase 以 15–25 个完成语义核对、界面接入和验证为上限；复杂枚举、位掩码、交叉依赖按 5–10 个估算。超出部分进入同类续批，每批仍约 1 人天。
- 每批维护字段状态：待核实 / 已定义 / 已实现 / 已验证 / 系统管理 / 不适用。不能把 conf 清单行数直接当成需要实现的控件数。
- 每个 phase 完成后，填写本文末尾的实际记录。涉及字段变更时，同步更新实现清单；未完成的验收项保留为未完成。

## 产品约定

1. 首页按玩家概念分类，不按 conf 文件名分组；支持搜索、查看已修改项。
2. 编辑写入草稿，明确区分未保存、已保存待重启、正在生效的值。
3. 数值显示真实单位。倍率、百分比和时间换算由字段定义负责，不在 View 中散落转换逻辑。
4. 配置持久化在 App 中，再生成 `ServerConfiguration` 覆盖内容。不能直接编辑会被重建的 `conf/import`。
5. 系统默认由基础配置和 App 必需覆盖共同组成；恢复默认删除用户覆盖，不能移除内部连接与客户端兼容设置。
6. 首版保存后完整重启服务，不承诺热更新。服务器未运行时只保存，下次启动应用。
7. 第一阶段先做可运行闭环，再扩展字段，最后接入 Patron。
8. 对全部配置做明确去向分类，不要求把数据库、内部连接、开发工具等都做成玩家可编辑控件。

## 工期理解

基线为 44 个约 1 人天工作包，**另加标量字段续批、复杂结构续批和必要缺陷修复**。这不是“44 天完成全部 986 行”的承诺；清单还含候选、重复作用域和系统管理项。Phase 25 完成后，根据剩余真实字段和复杂度重估完整工期。

首个可用闭环约 9 人天；常用版本基线约 19 人天，再加必要字段续批。单独交付常用版本的 Patron 接入与发布，另按 Phase 39–44 估算，不能省略购买及失败状态验证。

## 每个 phase 的完成定义

- 对应任务与验收标准完成，并记录实际验证方式和结果。
- 用户可见新增内容有中英文文案；依赖、单位和生效时间明确。
- 涉及配置转换、合并、持久化、状态机时做针对性验证；只新增静态标签不机械增加测试。
- 不破坏 App 必需覆盖，不能丢失未编辑的用户配置。
- 实现清单状态同步；残余问题有明确后续 phase。
